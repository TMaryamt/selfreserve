# SelfReserve (سلف‌رزرو)

وب‌اپلیکیشنی که به‌جای دانشجو وارد سامانه سلف دانشگاه میشود و غذا رزرو میکند.

- **بک‌اند:** Django + Django REST Framework (این ریپو، به مسئولیت مریم)
- **فرانت:** React (تیم فرانت و UI/UX)

این فایل مرحله‌به‌مرحله میگوید چطور پروژه را روی سیستم خودتان اجرا کنید و چطور با هم کار کنید. **اگر در هر مرحله گیر کردید، بخش «مشکلات رایج» آخر فایل را بخوانید.**

مستندات آدرس‌های API (چه چیزی بفرستید و چه چیزی میگیرید) در فایل [`API.md`](API.md) است.

## 0. چیزهایی که باید از قبل نصب باشند

| برنامه | نسخه | چطور چک کنم |
|---|---|---|
| Python | **3.12 یا بالاتر** | در ترمینال: `python --version` |
| Git | هر نسخه | `git --version` |
| VS Code | هر نسخه | |
| Node.js | برای React | `node --version` |

> Django 6 با Python پایین‌تر از 3.12 کار نمیکند. اگر نسخه شما پایین‌تر است، اول Python جدید نصب کنید (و موقع نصب تیک **Add Python to PATH** را بزنید).

## 1. گرفتن پروژه از گیت‌هاب

اول مطمئن شوید دعوت‌نامه (Invitation) ریپو را در ایمیل یا گیت‌هاب **Accept** کرده‌اید.

یک ترمینال باز کنید و بزنید (به جای `آدرس_ریپو` همان آدرس دکمه سبز **Code** در صفحه گیت‌هاب):

```cmd
cd Desktop
git clone آدرس_ریپو
cd اسم_پوشه_ریپو
code .
```

- `git clone` یعنی «یک کپی کامل از پروژه را روی سیستم من بگیر».
- `code .` پوشه را در VS Code باز میکند.

> **کد را از جای دیگر کپی‌پیست نکنید.** همیشه با `git clone` و `git pull` کار کنید تا همه یک کد داشته باشیم.

## 2. ساخت محیط مجازی (فقط یک بار)

محیط مجازی یک «جعبه جدا» برای کتابخانه‌های پایتون این پروژه است تا با پروژه‌های دیگرتان قاطی نشود. هر نفر روی سیستم خودش میسازد و **در گیت نمیرود**.

در ترمینال VS Code (`` Ctrl+` ``)، در پوشه‌ای که فایل `manage.py` هست:

```cmd
python -m venv venv
venv\Scripts\activate
```

بعد از فعال شدن، اول هر خط ترمینال باید `(venv)` ببینید.

**اگر ترمینال شما PowerShell است** (اول خطش `PS` دارد) و خطای «running scripts is disabled» داد، یک بار این را بزنید و دوباره `venv\Scripts\activate` را اجرا کنید:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

**یادتان باشد:** هر بار که ترمینال جدید باز میکنید، باید دوباره `venv\Scripts\activate` بزنید (تا `(venv)` را ببینید).

در VS Code هم interpreter را انتخاب کنید: `Ctrl+Shift+P` ← `Python: Select Interpreter` ← گزینه‌ای که `venv` دارد.

## 3. نصب کتابخانه‌ها (فقط یک بار، و بعد از هر `git pull` که `requirements.txt` عوض شده)

با `(venv)` فعال:

```cmd
pip install -r requirements.txt
```

`-r` یعنی «از روی این فایل همه کتابخانه‌ها را نصب کن». این کار باعث میشود همه نسخه یکسان از کتابخانه‌ها داشته باشیم.

اگر نصب کند بود یا خطای timeout داد (در ایران رایج است)، از میرور استفاده کنید:

```cmd
pip install -r requirements.txt -i https://package-mirror.liara.ir/repository/pypi/simple
```

## 4. ساخت کلید رمزنگاری (فقط یک بار، فقط برای سیستم خودتان)

اپ رمز سلف کاربرها را **رمزنگاری‌شده** نگه میدارد و برای این کار به یک کلید نیاز دارد که در کد و گیت نیست.

**اگر این مرحله را انجام ندهید،** همه‌چیز کار میکند، جز «اتصال به سلف» که خطای `SELF_ENCRYPTION_KEY تنظیم نشده است` میدهد.

**الف) ساخت کلید:**

```cmd
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

یک متن حدود 44 حرفی چاپ میشود که آخرش `=` دارد.

**ب) ذخیره کلید در ویندوز** (به جای `کلید` همان متن را بنویسید، با کوتیشن):

```cmd
setx SELF_ENCRYPTION_KEY "کلیدی که ساختید"
```

**ج) تمام پنجره‌های VS Code را کامل ببندید و دوباره باز کنید.** فقط بستن ترمینال کافی نیست، چون `setx` فقط برنامه‌هایی را اثر میدهد که بعد از آن باز شوند.

**د) چک کنید:** در ترمینال جدید (با `(venv)`):

```cmd
python -c "import os; print(bool(os.environ.get('SELF_ENCRYPTION_KEY')))"
```

باید `True` چاپ شود.

**قواعد کلید:**
- کلید هر نفر مال خودش است. **به کسی ندهید و در گیت و چت نگذارید.**
- اگر کلید را گم کنید، فقط اطلاعات سلف ذخیره‌شده در دیتابیس **خودتان** باز نمیشود و دوباره وصل میکنید. مشکل جدی نیست.

---

## 5. ساخت دیتابیس (فقط یک بار، و بعد از هر `git pull` که پوشه `migrations` عوض شده)

دیتابیس هر نفر روی سیستم خودش است (فایل `db.sqlite3`، که در گیت نیست). جدول‌ها را با این دستور میسازید:

```cmd
python manage.py migrate
```

اگر دستور بدون خطا تمام شد و چند خط `OK` دیدید، درست است. اخطار `staticfiles.W004` درباره پوشه `static` بی‌خطر است. اگر خواستید برود، یک پوشه خالی به اسم `static` کنار `manage.py` بسازید.

اختیاری: ساخت کاربر ادمین برای دیدن دیتابیس در `/admin/`:

```cmd
python manage.py createsuperuser
```

## 6. اجرای سرور

```cmd
python manage.py runserver
```

سرور روی `http://127.0.0.1:8000` اجرا میشود. **این ترمینال را باز بگذارید** (برای قطع کردن `Ctrl+C`).

**تست سالم بودن سرور:** در مرورگر این آدرس را باز کنید:

```
http://127.0.0.1:8000/api/auth/me/
```

اگر یک صفحه با متنی شبیه `Authentication credentials were not provided` دیدید، یعنی سرور درست بالا آمده (این خطا طبیعی است چون هنوز وارد نشده‌اید).

> هر بار که فایل‌های پایتون عوض شوند، سرور خودش دوباره راه میافتد. فقط اگر پوشه یا اپ تازه اضافه شد، یک بار با `Ctrl+C` ببندید و دوباره اجرا کنید.

## 7. وصل شدن React به بک‌اند

- آدرس پایه API: `http://127.0.0.1:8000`
- بک‌اند فقط به این آدرس‌های فرانت اجازه میدهد (CORS): `http://localhost:3000` و `http://localhost:5173`. **اگر React شما روی پورت دیگری اجرا میشود، به مریم بگویید.**
- بعد از ورود یا ثبت‌نام، یک **توکن** میگیرید. آن را نگه دارید و در همه درخواست‌های بعدی (به جز ثبت‌نام و ورود) در هدر بفرستید:

```
Authorization: Token <token>
```

نمونه کد (JavaScript):

```js
const API = "http://127.0.0.1:8000";

// ورود
async function login(username, password) {
  const res = await fetch(`${API}/api/auth/login/`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ username, password }),
  });
  const data = await res.json();
  if (!res.ok) throw new Error(data.detail || "خطا");
  localStorage.setItem("token", data.token); // نگه داشتن توکن
  return data.user;
}

// یک درخواست با توکن
async function getMe() {
  const res = await fetch(`${API}/api/auth/me/`, {
    headers: { Authorization: `Token ${localStorage.getItem("token")}` },
  });
  if (res.status === 401) {
    // توکن نامعتبر: کاربر را به صفحه ورود ببرید
  }
  return res.json();
}
```

**نکات مهم برای کارتان:**

1. **درخواست‌های `/api/self/...` چند ثانیه طول میکشند** (هر بار سرور باید وارد سامانه سلف شود). حتماً حالت loading نشان بدهید و دکمه را تا آمدن جواب غیرفعال کنید.
2. اگر جواب `401` آمد، کاربر وارد نیست. توکن را پاک کنید و به صفحه ورود بروید.
3. پیام‌های `detail` در خطاها فارسی هستند و میتوانید مستقیم به کاربر نشان بدهید.
4. **صفحه بازیابی رمز:** ایمیل بازیابی لینکی به این شکل دارد: `http://localhost:5173/reset-password/<id>`. پس باید صفحه‌ای در مسیر `/reset-password/:resetId` بسازید که `resetId` را از آدرس بخواند و با رمز جدید به `/api/auth/reset-password/` بفرستد (جزئیات در `API.md`). اگر پورت React شما `5173` نیست، به مریم بگویید تا آدرس عوض شود.
5. **در حالت توسعه ایمیل واقعی نمیرود.** وقتی «فراموشی رمز» را میزنید، لینک بازیابی در **ترمینال سرور** (همان که `runserver` در آن است) به شکل خوانا چاپ میشود، با پیشوند `RESET LINK:`. آن را کپی کنید و در مرورگر باز کنید.

## 8. تست API بدون React (اختیاری ولی مفید)

در ریشه پروژه چند فایل تست هست. سرور باید در یک ترمینال دیگر روشن باشد:

```cmd
python test_api.py
python test_reset_api.py
```

چیزی خراب نمیکنند و کاربر آزمایشی میسازند. فایل‌های `test_self_api.py`، `test_menu_api.py`، `test_reserve_api.py` و `test_preferences_api.py` به **حساب واقعی سلف** نیاز دارند (مخصوص مریم برای تست رزرو). **شما لازم نیست آن‌ها را اجرا کنید.**

---

## 9. دیدن فهرست غذاها و منو (حساب سلف)

فهرست غذاها (`/api/self/foods/`) در ابتدا **خالی** است و با گرفتن منو (`/api/self/menu/`) پر میشود. منو فقط برای کاربری کار میکند که اطلاعات سلف خودش را ثبت کرده باشد.

شما هم دانشجوی دانشگاه هستید، پس میتوانید در برنامه خودتان با **حساب سلف خودتان** وصل شوید (صفحه «اتصال به سلف»). چند قاعده:

- **فقط با حساب خودتان** تست کنید، نه حساب دیگران.
- رمز سلف را به کسی نگویید و در کد، گیت و اسکرین‌شات نگذارید.
- **رزرو واقعی از اعتبار شما کم میکند.** برای تست، ارزان‌ترین غذا را رزرو کنید و بلافاصله لغو کنید (لغو اعتبار را برمیگرداند).
- درخواست‌های پشت‌سرهم و زیاد نفرستید، تا حساب موقتاً قفل نشود.

## 10. کار گروهی با گیت

### قواعد

1. **هر نفر روی فایل‌های خودش کار کند.** فرانت فقط پوشه React (اگر داخل همین ریپو است، پوشه `frontend/`). بک‌اند (پوشه‌های `accounts`، `reservations`، `selfreserve`، `manage.py`) فقط با مریم.
2. **روی `main` مستقیم کار نکنید.** هر نفر شاخه (branch) خودش را داشته باشد.
3. **قبل از شروع هر بار کار، `pull` کنید.**
4. اگر به API چیزی نیاز دارید که نیست، به مریم بگویید، خودتان کد بک‌اند را عوض نکنید.

### شاخه خودتان (فقط یک بار)

```cmd
git checkout -b frontend-اسم_شما
```

### چرخه هر روز

**1) قبل از شروع، آخرین تغییرات را بگیرید:**

```cmd
git checkout main
git pull
git checkout frontend-اسم_شما
git merge main
```

اگر بعد از `pull` فایل `requirements.txt` یا پوشه `migrations` عوض شده بود، دوباره `pip install -r requirements.txt` و `python manage.py migrate` بزنید.

**2) کار کنید.**

**3) بعد از هر کار کوچک:**

```cmd
git add .
git commit -m "توضیح کوتاه کاری که کردید"
git push -u origin frontend-اسم_شما
```

(`-u origin ...` فقط بار اول لازم است، بعدش فقط `git push`.)

**4) ادغام کار در `main`:** در گیت‌هاب یک **Pull Request** بسازید (بعد از `push` گیت‌هاب خودش دکمه «Compare & pull request» را نشان میدهد). مریم بررسی و ادغامش میکند.

### چه چیزهایی نباید در گیت بروند

`venv/`، `node_modules/`، `db.sqlite3`، `.env` و هر چیزی که رمز یا کلید دارد. این‌ها در `.gitignore` هستند. قبل از `git add .` یک بار `git status` بزنید و ببینید چه فایل‌هایی میروند.

## مشکلات رایج

| مشکل | علت و راه‌حل |
|---|---|
| `python` شناخته نمیشود | Python نصب نیست یا به PATH اضافه نشده. دوباره نصب کنید و تیک **Add Python to PATH** را بزنید. |
| اول خط ترمینال `(venv)` ندارد | محیط مجازی فعال نیست. `venv\Scripts\activate` را بزنید. |
| `pip install` خطای timeout میدهد | از میرور استفاده کنید (بخش 3). |
| `ModuleNotFoundError: No module named ...` | `(venv)` فعال نیست یا `pip install -r requirements.txt` زده نشده. |
| `SELF_ENCRYPTION_KEY تنظیم نشده است` | بخش 4 را انجام نداده‌اید، یا بعد از `setx` تمام پنجره‌های VS Code را نبسته‌اید. |
| `no such table: ...` | `python manage.py migrate` را بزنید. |
| `OperationalError` یا ارور مایگریشن بعد از `pull` | دوباره `python manage.py migrate` بزنید. اگر باز هم ارور داد و دیتابیس شما مهم نیست، فایل `db.sqlite3` را پاک کنید و دوباره `migrate` بزنید. |
| ارور CORS در مرورگر (`blocked by CORS policy`) | پورت React شما در لیست مجاز نیست. پورت را به مریم بگویید. |
| همه درخواست‌ها `401` برمیگردانند | توکن را نفرستاده‌اید یا فرمتش اشتباه است. باید دقیقاً `Authorization: Token <token>` باشد (کلمه `Token` با یک فاصله). |
| `403` یا `CSRF` | آدرس را اشتباه نوشته‌اید. آدرس‌های API با `/api/` شروع میشوند و آخرشان `/` دارند. |
| درخواست‌های سلف خیلی کند هستند | طبیعی است (چند ثانیه)؛ حالت loading نشان بدهید. |
| `Error: That port is already in use` | سرور دیگری روی پورت 8000 روشن است. ترمینال‌های قبلی را ببندید یا `python manage.py runserver 8001` بزنید. |
| `git push` خطای دسترسی میدهد | دعوت‌نامه ریپو را Accept نکرده‌اید. |
| بعد از `git pull` تداخل (conflict) پیش آمد | هر دو نفر یک فایل را عوض کرده‌اید. با مریم هماهنگ کنید و خودتان حل نکنید. |

## چیزهایی که هنوز آماده نیست

- منوی **هفته آینده** (فعلاً فقط وعده‌هایی که الان قابل رزرو هستند)

وقتی آماده شدند، در `API.md` اضافه میشوند.
